# Электронный журнал успеваемости школы

[![build](https://github.com/IT-GSTU/ITP-31_borowoi_coursework/actions/workflows/build.yml/badge.svg?branch=main)](https://github.com/IT-GSTU/ITP-31_borowoi_coursework/actions/workflows/build.yml)
[![build(личный репозиторий)](https://github.com/borowoi/CourseWorkBD/actions/workflows/build.yml/badge.svg?branch=main)](https://github.com/borowoi/CourseWorkBD/actions/workflows/build.yml)

Курсовой проект по дисциплине «Разработка приложений баз данных для информационных систем»
(специальность 6-05-0611-01 «Информационные системы и технологии», 2026–2027 учебный год).
Вариант № 3: «Электронный журнал успеваемости школы».

## Возможности

- Справочники: классы, учащиеся, учителя, учебные предметы (с нагрузкой по часам в неделю по параллелям)
  с добавлением, изменением и удалением записей, проверкой вводимых данных, фильтрацией, сортировкой
  и постраничным выводом.
- Уроки и журнал: отметки (устный ответ, самостоятельная, контрольная, лабораторная) и пропуски
  (болезнь, уважительная причина, без уважительной причины).
- Итоговые отметки за четверти и год рассчитываются автоматически (представление `v_FinalGrades`).
- Отчёты: журнал класса по предмету за четверть со средним баллом, отметки и пропуски учащегося
  за период, успеваемость класса и параллели (средняя оценка, число неуспевающих, рейтинг предметов),
  посещаемость по классам и предметам за период.
- Выбранные фильтры, сортировка и страница списка сохраняются при переходах между страницами.

## Архитектура

Традиционная многослойная архитектура (зависимости направлены сверху вниз):

```
SchoolJournal.Web  →  SchoolJournal.BusinessLogic  →  SchoolJournal.DataAccess
 (ASP.NET Core MVC)     (DTO, службы, расчёты)         (EF Core, репозитории, UnitOfWork)
```

| Проект | Назначение |
|---|---|
| `src/SchoolJournal.DataAccess` | Сущности, контекст `SchoolJournalDbContext`, репозитории, единица работы |
| `src/SchoolJournal.BusinessLogic` | Объекты передачи данных, службы приложения, правила предметной области, отчёты |
| `src/SchoolJournal.Web` | Контроллеры, модели представлений, представления Razor |
| `tests/SchoolJournal.Tests` | Модульные тесты (xUnit, EF Core InMemory) |
| `database/` | Сценарии T-SQL: создание базы, начальное заполнение, контроль объёмов, очистка |

## Технологии

.NET 10, ASP.NET Core MVC, Entity Framework Core 10, MS SQL Server (LocalDB / Express / Developer),
Bootstrap 5, xUnit, GitHub Actions.

## Развёртывание

Требуются: .NET 10 SDK, MS SQL Server (подойдёт LocalDB из состава Visual Studio) и SSMS либо
Visual Studio для выполнения сценариев.

1. Склонировать репозиторий.
2. Выполнить по очереди сценарии из папки `database` (на сервере, указанном в строке подключения):
   1. `01_create_database.sql` — создаёт базу `SchoolJournalCourseDB`, таблицы, индексы и представление;
   2. `02_seed_data.sql` — заполняет тестовыми данными (120 учителей, 104 предмета, 110 классов,
      около 2 100 учащихся, около 22 000 уроков, около 180 000 записей журнала);
   3. `03_check_counts.sql` — контроль объёмов (необязательно).
3. При необходимости изменить строку подключения `DefaultConnection` в
   `src/SchoolJournal.Web/appsettings.json`.
4. Запустить приложение:

   ```
   dotnet run --project src/SchoolJournal.Web
   ```

   и открыть адрес, указанный в консоли.

Для повторного заполнения базы сначала выполняется `99_clear_data.sql` (удаляет все данные).

## Тесты и непрерывная интеграция

```
dotnet build
dotnet test
```

Рабочий процесс GitHub Actions (`.github/workflows/ci.yml`) при каждом изменении в репозитории
собирает решение и запускает модульные тесты; результаты тестов сохраняются как артефакт запуска.
Состояние последнего запуска показывает эмблема в начале файла.
